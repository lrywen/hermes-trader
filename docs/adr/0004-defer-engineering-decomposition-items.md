## 背景

「综合检查与评估报告」（2026-09-19）建议 5 要求：P1 恢复前冻结 executor 叶子提取，并把
**P1-step③ 与 P2-1/2/3/5 正式标记为 deferred（M3 后评估）**。随后 W4–W7 已完成结局 B 裁定、
换周期与四类换策略范式的全部证据链，以及 B-6~B-11、D-7、guard 杠杆/成本表守卫和 B-12/13 上线。

本 ADR 把报告中**剩余仍挂账、但已被评估为"此刻不应实施"的工程项**正式收口为 Deferred，逐项给出：
为什么不做、维持它的成本、以及**什么客观条件出现时才重新评估**。目的是消除"疑似遗漏"的账，
同时防止在负期望结论下投入高风险/零价值改造。

## 决策

以下五项登记为 **Deferred（有意延后，非未完成缺陷）**。在各自触发条件出现前，不投入实施；
任何一项要提前推进，须新开 ADR 并说明触发依据。

### DFR-1 — P1-1 step② 高风险半（bracket/lifecycle 函数搬离 executor）

- 范围：`_place_backup_sl` / `_place_tp_scale_out` / `_register_filled_position` /
  `_reconcile_unknown_order_result` / `sync_exchange_sl` / `retry_pending_sl`（6 个仍在 executor）。
- 不做原因：它们持有跨进程入场 flock、pending-SL 持久化、DSL 注册写入；锁释放在约 20 个返回分支
  成对配对。纯搬位置零行为收益，却在真实下单路径引入高回归风险，现有测试不足以保证锁/写不错位。
  低风险半（orders 门面 re-export）已完成，边界写在 orders.py docstring。
- 维持成本：executor 偏大，认知成本高；不影响运行正确性。
- **再评估触发条件**：① 出现一个 CI 下界 >0 的 LIVE 候选策略（解构服务于活跃迭代而非负期望代码）；
  且 ② 先补齐能钉死锁获取/释放与 pending-SL 写入配对的特征化测试。两者齐备才搬。

### DFR-2 — P1-1 step③（`maybe_execute` 进一步拆五段）

- 现状：该函数实质已是**编排外壳**——block/sizing/placement/register/brackets 各阶段均抽成命名
  helper；1,157 行的体积主要来自内联 sizing-v2 计算与详细注释，而非未拆分的单体逻辑。
- 不做原因：继续切分是表层美化，零行为收益；内联 sizing 数学与下单/锁状态深度耦合，强拆风险高。
- **再评估触发条件**：同 DFR-1——有正期望策略需在该路径高频迭代时，随 DFR-1 一并做，不单独美化。

### DFR-3 — P2-1 scripts 瘦身 与 P2-3 策略插件化

- 现状：scripts 现 83 个 .py（白名单使其不进生产镜像，风险仅限仓库可维护性）；无策略插件机制。
- 不做原因：瘦身/插件化是大规模机械改造，当前所有策略范式均被证伪、无活跃第二策略，插件化
  没有服务对象；属为假设需求设计。
- **再评估触发条件**：当**确有第二个需并行维护的策略/范式**进入预注册（而非排除法剩余）时，
  先做插件化承载，再据插件边界收敛 scripts；无第二策略则不做。

### DFR-4 — P2-2 server/dashboard 主体瘦身

- 现状：7 个业务路由已外移到 dashboard_routes（含 `__init__` 为 8 文件）；server 2,671 /
  dashboard 3,103 主体仍巨型。
- 不做原因：最高频改动的路由层已解耦，剩余主体搬动面大、测试收益低。
- **再评估触发条件**：需对 server/dashboard 主体做实质性功能改造（而非仅移动）时，借那次变更
  顺带瘦身；不为瘦身而瘦身。

### DFR-5 — 研究负载物理隔离 与 R6（docker exec 白名单旁路）

- 现状：研究负载仅逻辑隔离（运行侧 mem_limit 1g / cpus 2；宿主 venv 预热不受配额约束），
  无独立研究容器/卷；白名单只控镜像内容，`docker exec` 可旁路。
- 不做原因：物理隔离需新增独立 compose 服务/卷与凭据边界，属运维/基础设施项目；R6 的 exec 旁路
  本质是宿主机 root 能力，应用层无法消除，只能靠宿主机访问控制收敛。
- **再评估触发条件（物理隔离）**：研究重负载常态化（多次全池预热/重回测）且观测到对生产容器
  CPU/内存/延迟的实际挤压时，新增独立 research 服务。
- **再评估触发条件（exec 旁路）**：主机需授予非完全可信主体访问时，通过宿主机角色/命令白名单
  （如限定可 exec 的命令）收敛；单主机单操作者场景下维持现状、记录已知。

## 不属于 Deferred、仍需另行决策的事项

- **ADR-0003 末尾方向决策**（注资小资金实盘取样 P-B maker / 暂停研发维持 SHADOW）——是待操作者
  拍板的风险决策，**不被本 ADR 关闭**。
- **C/D 等数据项**（C-1/3/5/6、D-2/4/5/8）——前置已解除，纯待样本时间积累，非工程缺口。

## 后果

- 报告 §1.1/§3/§5 建议 5 的账面全部闭环：未完成项要么已完成、要么在本 ADR 正式 Deferred 并带触发条件。
- 不改变任何交易语义、资金安全守卫与生产配置；系统继续 SHADOW 运行。
- 未来评审只需核对各触发条件是否出现，而无需重新判断"这些是不是漏做了"。
