# M-11 触发器确认延迟（first_cross vs confirmed）入场假设预注册

> 日期：2026-10-24（冻结于 M-1 首次分析日 2026-10-28 之前）
> 背景：M-1（OFI 微结构）在严格预注册口径下已可预期不通过；同时 155 笔实盘/影子成交的复盘（`.review/plan_2026-10-22.md` §3）显示 **54.8% 的交易 MFE 从未触及 +1.5%**，瓶颈在「入场时点」而非出场参数。该复盘提出候选机制假设 H-new：*触发器确认延迟是 MFE 左尾的主因*。
> 本文件用途：**在重放 book-raw 全量触发事件之前**固定假设、对照定义、标签、推断口径与判定阈值。按计划 §2.4，本文于 10-28 前写就、10-29 启动，使下一研究线程零空转，且不破坏「首次分析不早于 10-28」的 M-1 纪律（本文不含任何 M-1 统计量，也不据此改变 M-1 执行）。

---

## 0. 先固定立场：本假设的第一步是证伪它自己

计划 §3.3 / §4.4 的既有观察**与「延迟有害」方向相反**：

- `extension ≥ 2 ATR`（更晚/更延伸才进）组 MFE 1.321 / 胜率 50.0%，而 `0~1 ATR`（更早、刚破位就进）组 MFE 0.431 / 胜率 25.0% —— **越晚进反而越好**。
- `breakout(confirm_bars)` 的设计本意（`hermes_trader/indicators/triggers.py:128-136`）正是用 N 根收盘确认**过滤单根插针的假突破**；若确认在过滤假突破，延迟应当是*有益*的。

因此本文不预设「去掉确认能赚钱」，而是把首轮检验设计成对该机制的**严格证伪**。只有在配对口径下「更早入场」带来的**可执行净收益**显著为正且过经济阈值，才推翻上述相反证据、保留该机制；否则按 §5 关闭「入场时点」这条改造路径。

> 数据隔离声明（防 HARKing）：上述反向线索来自 **155 笔已实现的实盘/影子成交**（影子账本按 1m K线评估出场）。该 155 笔**不进入** M-11 任何样本。M-11 的样本是对 `book-raw` 1s 盘口快照独立重放出的触发事件（见 §2），与那 155 笔不同源、未经人工逐笔翻阅。假设虽从 155 笔观察中萌生，检验用的却是未经翻阅的全量事件 + 时间样本外切分。

## 1. 预注册主假设（唯一主假设）

### H1（primary，方向性）：在同一触发事件内，确认延迟使可执行净收益变差

**方向（先固定）**：对每一个会被 N 根确认接受的突破事件，`first_cross`（价格首次穿越 prior-range edge 的那根 bar）入场，其后续**可执行净收益**严格优于 `confirmed`（持有满 `confirm_bars` 后那根 bar）入场。即配对差

```
Δ_i = net_bps(first_cross_i) − net_bps(confirmed_i)
```

的总体均值 **> 0**。若 Δ ≤ 0（更早进不更好、甚至更差），主假设被证伪，与 §0 的反向证据一致。

**对照定义（同事件配对，不做组间比较）**

- 触发原型固定为 `indicators/triggers.py:breakout`，参数**严格沿用生产配置**（`deploy/prod_override.json` 的 `breakout_*`，等价于 `agents/config.py` thresholds）：`lookback=48`、`min_rvol=1.8`、`rvol_window=20`、`atr_period=14`、`atr_score_mult=3.0`、**`confirm_bars=3`**；**不启用** launch-capture 的 flow 自适应确认（`flow_confirm=None`），以隔离「N 根持有确认」这一单一机制。
  > 注：`triggers.py:breakout` 的函数签名 fallback 是 `min_rvol=1.5 / confirm_bars=2`，但生产经 `breakoutConfirmBars`/`breakoutMinRvol` 覆盖为 **3 / 1.8**（见 `triggers.py:841` 读取、`config.py:40,43`、`prod_override.json:903`）。本预注册以**生产生效值**为准，不用函数 fallback。
- 对每根 5m bar 跑 breakout（lookback=48 ⇒ prior range = 突破窗前 48 根 5m = 4h）。
- `first_cross` 时点 = 代码中 `first_break_idx = len(candles) - confirm_bars` 指向的那根 bar（窗口内**首次**收盘越过 edge 的 bar，见 `triggers.py:202`）。
- `confirmed` 时点 = 确认窗最后一根 bar（现行生产入场点）。confirm_bars=3 在 5m 上 = **15 分钟确认延迟**。
- **配对资格**：仅当该事件确实「持有满 `confirm_bars` 根且每根都收在 edge 同侧」（即生产口径下会 fired）时，才纳入配对。被确认窗拒绝的假突破**不纳入主检验**（它们没有 confirmed 入场，无法配对），仅在 §3 机制佐证里单列为「first_cross 会进但 confirmed 不进」的选择性人群。
- 主口径固定 `confirm_bars = 3`（生产值，5m 上 = 15 分钟延迟）。`confirm_bars ∈ {1, 2}` 仅作稳健性，不顶替主结论。

**入场价（PIT，杜绝前视）**

- 两个入场点的成交价都取该 5m bar **收盘时刻**的可执行价，从 `book-raw` 1s 快照对齐：
  - first_cross 腿：t 时刻 **ask** 买（做多）/ **bid** 卖（做空）。
  - confirmed 腿：t + confirm_bars×5m 时刻的 ask/bid。
- 标签价（平仓）统一用持仓期末的 **bid/ask**（多仓平仓卖在 bid），mid 仅用于机制描述，不用于净收益。
- 数据对齐：5m bar 收盘时刻映射到该秒的 book-raw 帧；缺帧用前向最近一帧（只允许用 ≤ 该时刻的帧），并在报告中给出缺帧/陈旧帧比例。

**标签与持有（label，先固定）**

- 主 horizon `h = 300s`（与 M-1 主口径一致，便于跨假设比较）；次 horizon `h ∈ {15m, 60m}` 仅稳健性。
- 固定时间平仓，**不**在标签窗口内提前止盈/止损——主检验回答的是「更早进的同一笔裸信号值多少钱」，出场规则差异属另一条改造路径（P2-1，M-1 后另案）。
- 方向：上行突破做多、下行突破做空，两腿方向相同（差异只在入场时点）。

**成本（可执行口径，与 M-1 一致）**

- 每条 taker 腿 = 实测 taker 费率 + 开仓 cross 半价差（用该入场时刻 book-raw 实测 spread，不假设 maker 成交）。
- Δ_i 是两腿各自扣足成本后的净 bps 之差；由于两腿方向/币种/出场相同，其差额主要由「entry 滑点 + 确认窗内价格漂移」驱动，但仍按各自完整成本独立计算后再相减，不做解析近似。

### H2（secondary，机制）：确认窗内的价格漂移解释 Δ 的方向

- 记录确认窗内 `(entry_confirmed − entry_first_cross)` 的带符号漂移（现货点，按突破方向归号）。
- 假设：若 H1 成立（Δ>0），主因应是「确认窗内价格朝不利方向漂移」（追高成本），且该漂移在高 RVOL / 高 extension 事件中更大。
- 作为次要假设，按 §3 多重检验校正后报告，不能替代 H1 下结论。

### H3（exploratory，不计入通过计数）

- 「first_cross 会进、confirmed 拒绝」的假突破人群后续收益（量化确认机制到底挡掉了多少坏交易）。
- MFE 分布、`confirm_bars=1/2/3` 的全量（含非配对）描述统计。
- 这些只回答机制、不决定 H1 通过与否；exploratory 一律不作为上线依据。

## 2. 样本与时间切分

- **样本来源**：`book-raw/date=YYYY-MM-DD/COIN.jsonl[.gz]`（1s 快照，2026-09-28 起，保留 90 天）重放出的 5m K线 + 突破事件；币种集以「快照时点该币在 Top20 榜」为准（同 M-1 §0）。
- **明确排除**：`.review/plan_2026-10-22.md` 使用的 155 笔实盘/影子成交记录，不进入事件样本、不用于任何阈值。
- **train / test 切分（先固定）**：按**日期**前后各 50%。前 50% 天数仅用于确定数据清洗/对齐方式与（若有）标准化做法，不搜索任何阈值；后 50% 为**唯一报告检验结果的样本外区间**。事件定义、horizon、成本、经济阈值均不依赖 train 拟合。
- **去重叠**：同一币在确认窗 + 持有窗（共 confirm_bars×5m + h）内不重复计事件（同向事件取第一个），防止一段行情被两腿/多事件重复计数。
- **启动与首检**：2026-10-29 启动重放；首次分析报告只使用截至该日已落盘且分区已归档（`.gz`，即非当日 UTC 完整分区）的数据。
- **样本量门槛**：样本外**有效配对事件数 ≥ 500**。不足 500 判「样本不足」，延长采集而非降门槛或放宽配对资格。

## 3. 推断口径与判定阈值（全部先固定）

- **推断单位**：以时间块聚类的配对差序列 `{Δ_i}`。同一时刻跨币事件相关，主推断用**按时间块的 block bootstrap**：在每个重采样块内保留跨币的配对结构，对 Δ 做块内配对后求均值。块长主口径 **15m**（≥ 主 horizon 的 2×，与 M-1 一致），另报 1h 块稳健性。B=10000，seed 固定 `20261024`。
- 报告样本外 Δ 均值（净 bps/事件）的 95% CI。
- **通过判据（全部满足才算 H1 通过，任一不满足即证伪/关闭该方向）**：
  1. 样本外配对差均值的 95% block-bootstrap **CI 下界严格 > 0**（first_cross 确实更优，不是无差异）；
  2. 方向与预注册一致（Δ>0 ⇒ 更早进更优），**不接受翻号**。若 CI 上界 < 0（confirmed 显著更优），明确记录为「确认延迟有益」，关闭该改造方向并视为对确认机制的正向验证；若 CI 跨 0，记「无可检测差异」，同样不构成放宽确认的依据；
  3. 主口径（confirm_bars=3, h=300s）单独成立——不允许用 confirm_bars∈{1,2} 或 h∈{15m,60m} 格里某个显著的顶替；
  4. 多重检验：H1 为主假设不校正；H2 按 Holm（H1+H2 两家族）校正后仍需对应 CI 下界 > 0。H3 exploratory 不参与判定；
  5. 稳健性（不翻号即过，不要求都显著）：换 1h 块、剔最高波动 10% 时段、仅 BTC/ETH 子集、剔单一最大贡献币、`confirm_bars=1/2`、h∈{15m,60m}——Δ 方向一致（不为显著负）。
- **最小经济阈值（先固定）**：样本外配对差净均值 **≥ 3 bps/事件**（两腿各自扣足 taker + 实测半价差之后）。低于此值即便 CI 下界 > 0 也判「统计可见但不可交易」，不触发把 confirm_bars 调小的任何生产改动。
- 计划 §4.4 提到的「MFE 中位提升 ≥ 0.3 现货点」**降级为 H2/H3 的机制佐证指标，不作主判据**（MFE 不可兑现；主判据以可执行净 bps 为准）。

## 4. 去拟合纪律

- 不在事件样本上做网格/遗传搜索去找「最赚的 confirm_bars / horizon / 入场阈值」。对照定义、horizon、成本、块长、经济阈值、seed 在看数前固定于本文。
- 任何参数偏离必须新开假设、用未使用过的数据段检验，不回填本结论。
- 主结论只承认一个预指定配置（confirm_bars=3, h=300s, 配对 Δ）；稳健性格子只用于「会不会翻号」，不用于选最优。
- 不报告 in-sample 优化的年化；只报告样本外、扣足成本、带 bootstrap CI 的 Δ bps/事件，以及由事件频率推导的保守情景（标注为情景非承诺）。
- 本文不改变任何生产参数（尤其不预先把 `breakoutConfirmBars` 调小）；纯影子/历史重放研究。

## 5. 触发后的交付

- **若 H1 通过**（§3 判据全满足）：才进入「是否把确认从 3 降到 2（或 1）/ 引入 first_cross 限价试探」的工程评估，且必须先经过小额 LIVE 实测（执行滑点不能从盘口重放推断，见计划 §3.7），再谈生产改动。交付：固定对照逻辑 / 数据对齐与成本口径 / 样本外 Δ 净 bps + CI / 分 regime 与分 RVOL 拆解 / LIVE 实测方案。
- **若 H1 证伪或无经济价值**（预期方向，见 §0）：产出关闭结论——「入场时点」这条改造路径关闭，确认机制保留；剩余选项收敛到「降低下注强度 / 止损执行侧」，不在本文扩展。
- 无论通过与否，结果写入同目录结果文件 `m11_..._result_2026-10-*.md`。

## 6. 计划的复核动作

- 2026-10-29 后：首次配对检验（按 §1–§3），只报样本外结果。
- 若首次通过：在其后新增、本文未使用的数据分区上用**完全相同固定口径**做一次确认，不调参；确认时点与样本量届时按 ≥500 配对事件另行记录（追加节，不改写本文件）。

## 7. 与既有体系的关系（澄清，非假设）

- 本假设与 M-1 技术零耦合：M-1 走 book-raw → OFI → 5m mid 收益；M-11 走 book-raw 重放的 5m 突破 → 同事件两腿配对。两者只读同一份原始数据，不改数据、不共享参数，互不污染统计量。
- 治理地位：依据 ADR-0001「不限制 SHADOW 下的研究自由，只冻结真实资金出口」，本预注册属 SHADOW/历史研究，可在 10-28 前冻结、10-29 启动；它不触发任何真实资金出口改动。
