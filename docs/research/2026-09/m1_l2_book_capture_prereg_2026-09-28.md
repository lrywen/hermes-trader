## 1. 预注册主假设（唯一主假设，多重检验口径只对它负责）

### H1（primary）：订单流失衡 OFI 对短周期未来 mid 收益有正向样本外预测力

**方向（先固定）**：订单流净买入压力（OFI > 0）预测未来 mid **上涨**；OFI < 0 预测下跌。即信号与未来收益相关系数 > 0。

**特征定义（Cont 等 2014 口径，适配 1s 快照、best-10 档）**

逐快照对每币，基于前后两帧 best 档（必要时扩到前 k 档）计算 OFI。best-level 形式：

```
e_n = 1[Pn^b >= Pn-1^b] * Qn^b  - 1[Pn^b <= Pn-1^b] * Qn-1^b
      - 1[Pn^a <= Pn-1^a] * Qn^a  + 1[Pn^a >= Pn-1^a] * Qn-1^a
```

（P^b/P^a=best bid/ask，Q=对应挂量；价格不变时该项=本档挂量变化 ΔQ。）
深度扩展版 OFI-10：对 10 档分别按「同价位挂量变化 + 新价位进入/旧价位退出」求和，再用各档到 mid 的距离做固定权重衰减（权重 w_k = 1/k，**预先固定，不优化**）。

- 聚合窗口 W_OFI ∈ {**60s, 300s**}：把窗口内逐秒 e_n 求和，并用该窗口末档的 mid 价差或挂量做标准化（z = OFI / 窗口内 OFI 标准差，滚动只用过去数据）。**主口径固定 W_OFI=60s**；300s 仅作稳健性，不作为主结论。
- 不做参数搜索；阈值（如「OFI 极端分位才入场」）统一用**各币滚动过去 30 天的横截面+时序分位**，分位带 [0,10%) / (90%,100%] 预先固定。

**标签（label，先固定）**

- 主 horizon h = **5 分钟（300s）** 的 forward mid return：`y = (mid_{t+h} - mid_t)/mid_t`，mid=(best bid+best ask)/2。
- 次 horizon（稳健性，不决定主结论）：h ∈ {15m}。
- 标签用 mid 而非成交价，避免 bid-ask bounce 污染；同时单独报告「用 t 时刻 ask 买、t+h 时刻 bid 卖」的可执行口径（见成本）。

**入场→可执行收益（主检验用这个，而非裸相关）**

- 信号 z > +k（k 固定=对应过去30天 90 分位）→ 做多；z < −k → 做空；中间不交易。
- 持有 h=5m 后平仓，不提前止盈止损（检验的是「裸信号有没有毛 edge」）。
- 成本：每条腿 taker 费 + 开仓时 cross 半价差。回测口径采用 HL 真实 taker 费与该快照实测价差，**不假设 maker 成交**（P-B 已证明 maker 成交无法用历史验证）。

### H2（secondary，预注册但非主）：盘口失衡的「水平/斜率」预测变盘

- 特征：bid/ask 前 10 档**挂量的不对称**（bid 总量 − ask 总量，除以二者之和）、以及深度曲线斜率差。
- 假设：极端不对称 + 当前 mid 窄幅（低已实现波动）后，5/15m 收益朝堆积厚的一侧方向突破。
- 作为次要假设，显著性按 §3 多重检验校正后报告，**不能替代 H1 下结论**。

### H3（exploratory，明确标注，不计入「通过」计数）

- CVD / 价格背离、主动买卖压力。**当前数据无 tape，无法直接算 CVD**；仅在（a）后续补采逐笔成交，或（b）用「快照间 mid 变动 × 挂量变化」做近似代理时探索。
- 代理口径的结果一律标 exploratory，不作为策略上线依据。

## 3. 推断口径与判定阈值（全部先固定）

- **推断单位**：以「快照时刻」聚类——同一时刻跨 20 币的信号高度相关，不能把跨币当独立。主推断用**按时间块的 block bootstrap**：块长 ≥ 2×h（5m 信号 → 块长取 15m，另报 1h 块稳健性），块内保留跨币相关结构。
- 对**每笔可执行净收益（已扣成本）序列**做 block bootstrap（B=10000，seed=20260928），报告均值 bps/笔的 95% CI。
- **通过判据（全部满足才算 H1 通过，任一不满足即关闭该方向）**：
  1. 样本外净 bps/笔的 95% block-bootstrap **CI 下界严格 > 0**；
  2. 方向与预注册一致（OFI+ → 收益+），不接受翻号；
  3. 主口径（W=60s, h=5m）单独成立——不允许用稳健性格子（300s/15m）里某个显著的来顶替；
  4. 多重检验：H1 为主假设不校正；H2 作为次要假设按 Holm（H1+H2 两个家族）校正后仍需 CI 下界>0。exploratory H3 不参与判定；
  5. 稳健性（不翻号即通过，不要求都显著）：换 1h 块、剔最高波动 10% 时段、只看 BTC/ETH 子集、剔单一最大贡献币——结论方向一致。
- **最小经济阈值（先固定，防止「统计显著但太薄」）**：样本外净均值 ≥ **3 bps/笔**（扣足 taker+价差后）。低于此值即便 CI>0 也判定为「不可交易」，不触发上线。
- 样本量：30 天 × 20 币 × (24h × 12 次/h) ≈ 17 万潜在信号点，去重叠+分位过滤后预计数千笔可执行交易；若样本外有效交易笔数 < 300，判定「样本不足」，延长采集而非降门槛。

### 7.1 数学冲突（必须澄清，不是选参数）

- §1 要求分位/标准化用「各币滚动过去 30 天」；§2 要求「满 30 天做首次分析」，而采集自 2026-09-28 起。

- §2 已明文「前 50% 天数仅用于确定标准化/分位的计算方式（不搜索参数）」，即历史长度属可实现性细节，不是假设。

### 7.2 澄清 A：窗口 = expanding，上限 30 天

- 币 i 在 t 时刻的分位/z，只用该币 **t 之前（不含 t）** 的数据；回顾长度 = min(已有历史, 30 天)。
- 满 30 天后退化为 §1 的滚动 30 天；不足 30 天时用全部已有历史（不引入未来信息）。
- 分位带 [0,10%)/(90%,100%]、horizon、成本、经济阈值一概不变。

### 7.2.1 z 的分母（C1）

§1 原文「z = OFI / **窗口内** OFI 标准差」与「滚动只用过去数据」两句可指向两种分母，本节在看数前固定：

- **主口径**：`std_within` = 该 W 窗口内逐秒 `e_n` 的样本标准差（`ddof=1`）。理由：①贴合 §1 字面「窗口内」；②量纲上是 t 型统计量，天然跨币可比，支撑 7.3 的横截面排序；③不依赖 30 天历史，test 段早期不因历史不足而失真。
- **防护**：`n_frames < 10` 或 `std_within <= 0` 时该槽不触发（防止极安静盘口 z 爆炸）。
- **稳健性**：以「该币过去 W 窗口和的 expanding-30d 历史标准差」为分母重跑一次，作为 §3 判据 5 的第五项稳健性（只报是否翻号，不参与主判定）。

> 说明：本节不改变 H1 的方向、horizon、分位带与成本口径，只固定 z 的构造。

### 7.3 澄清 B：「横截面 + 时序」的组合顺序

> **执行单元更正（C2）**：横截面单元为槽号 `slot = t // h_s`（`h_s = 300`），**不是**精确毫秒时刻；本节第 2 条「同一快照时点 t」一律按槽号理解。量化规则见本节末「7.3 补充」。

§1 原文「各币滚动过去 30 天的横截面+时序分位」在单币内无法取横截面分位，必须固定组合顺序。**固定为「先逐币时序 z，再同时点跨币排序」**：

1. 时序（逐币）：`z_{i,t} = OFI_sum_{i,t}(W) / std_{i,t}(W)`，**分母按 7.2.1 固定**（主口径 = 窗口内逐秒 `e` 的样本标准差，`ddof=1`；历史标准差仅作稳健性）；`n_frames < 10`、`std <= 0` 或 expanding 历史 < 2 时不触发。
2. 横截面（同时点）：在同一快照时点 t，对全部在榜币的 `z` 排序，只对落在该时点 [0,10%) / (90%,100%) 的币触发。

- 顺序（先时序、后横截面）在看数前固定，不得事后调换；调换属新假设，按 §4 另起一期。
- 只做逐币时序分位而不做横截面闸，等于丢掉 §1 的「横截面」二字，故不采用。
- 预期影响：触发数低于逐币独立触发，但按 §3 估算仍远高于 300 笔；若实际不足 300 笔，按 §3 判「样本不足，延长采集」，不得降门槛。

#### 7.3 补充（C2 量化规则）

- 横截面单元：`slot = t // h_s`，`h_s = 300`；同一槽内全部在榜币参与排序。
- 每槽取 z 排名最高、最低各 `k = floor(0.10 × n_coins)` 个；`n_coins < 5` 时该槽不触发（10% 不足 1 个，横截面无意义）。
- `n_coins` 只计当槽有有效 z 的币；无有效 z（`n_frames < 10`、`std_within <= 0`、expanding 历史 < 2）的币不参与排序，也不触发。
- 时序带与横截面排名都是 z 的单调变换，交集自动同向，不会出现「时序在上带、横截面在下带」的矛盾。

### 7.7 判据实现细节（C3–C10 + 2 项新增）

> 本节只固定**实现细节**，不改变 §1–§3 的假设、方向、horizon、分位带、成本与经济阈值。编号跳过 §7.4–§7.6 是为了不重写既有段落（对外审计要求追加式修订）。

#### 7.7.1 判据 4 的操作化（C3）

§3 判据 4 原文「H1 为主假设**不校正**；H2 作为次要假设按 Holm（**H1+H2 两个家族**）校正」在数学上不能同时成立：2 元家族的 Holm 首步必用 α/2，必然也校正 H1。本节按下列方式执行，属**对原句的澄清**：

- **H1（主假设）**：单侧 bootstrap p < **0.05**，不校正。
- **H2（次要假设）**：单侧 bootstrap p < **0.025**（2 元 Holm 的保守上界，等价于 Bonferroni）。取保守方向，不放宽 H2。
- exploratory H3 仍不参与判定。

#### 7.7.2 p 值的来源（C4）

- 单侧 p = `#{bootstrap 均值 <= 0} / B`，`B = 10000`，`seed = 20260928`，与判据 1 的 CI **共用同一次重采样**（同一 block 划分、同一随机序列）。
- 与 `block_bootstrap_ci` 严格等价：`lo = means[249]`（B=10000 的 2.5% 位）；`means[249] > 0` ⟺ `#{<=0} <= 249` ⟺ `p < 0.025`。故判据 4 只报 p，CI 一并打印但不重复门控。
- H2 使用自己的成交序列，重采样仍按同一 block 划分独立生成，seed 规则相同。

#### 7.7.3 判据 5 ②「剔最高波动 10% 时段」（C5，与变更单有一处差异）

- 波动度量：该 slot **自身价格路径**的已实现波动 `RV_slot = sqrt(Σ_k (ln(mid_k / mid_{k-1}))²)`，`k` 遍历该槽内 1s mid 帧。
- **与变更单 C5 的差异及理由**：C5 提议 `|ln(mid_t / mid_{t-h})|`，那是**持有期收益的绝对值**，与被检验的 PnL 直接纠缠（会优先剔掉最大赢家与最大输家），且属结果变量而非波动。改用槽内路径 RV，只依赖该槽已发生的路径，不触碰 forward 收益。
- 剔除单元：**slot**（整槽、跨币一起剔），对齐 §3 原文「时段」。
- 阈值：test 段全部 slot 的 RV 的 **90 分位**；剔除严格大于者后重跑。
- 该剔除是 ex-post 诊断（用 test 段自身分布），只作稳健性，不进入主判定。

#### 7.7.4 判据 5 ④「剔单一最大贡献币」（C6，补充）

- 主口径：贡献 = 该币 test 段全部交易的 **Σ net_bp**；剔除最大者重跑。
- 追加：同时报 **leave-one-out 对均值的影响** `n_i × (mean_i − mean_all)` 最大的币，剔除后重跑。
- 判定：两者**任一翻号**即判据 5 = no（取更严方向）。
- 理由：Σ net_bp 混合了笔数与单笔 edge，而判据检验的是均值，故两种剔除都必须过。

#### 7.7.5 H2 的不对称分位带（C7）

- 沿用 [0,10%) / (90%,100%)，作用于 `depth_imbalance` 的**逐币 expanding-30d 分位**。
- 横截面确认与 §7.3 相同：同 slot 跨币排序，每侧 `k = floor(0.10 × n_coins)`。

#### 7.7.6 H2 的低波动条件（C8）

- `RV_30m = sqrt(Σ_{k=1..6} (ln(mid_k / mid_{k-1}))²)`，`k` 取最近 6 个 5m 槽的末帧 mid。
- 阈值：该币 expanding-30d 的 **30 分位**；`RV_30m <= 该分位` 视为「窄幅」。
- H2 触发 = 不对称极端 **且** 窄幅 **且** 横截面极端。

#### 7.7.7 H2 的 horizon（C9）

- 主口径 **5m（300s）** 决定 H2 判定；15m（900s）一并报出，仅作参考。

#### 7.7.8 新增特征 `depth_slope_diff`（C10）

- `s_b` = bid 侧累积挂量对档位序号的 LS 斜率 ÷ bid 侧总挂量；`s_a` = ask 侧同法。
- `depth_slope_diff = s_b − s_a`（>0 表示买盘远端更厚）。样本 < 2 档或总挂量 <= 0 返回 None。
- 不复用 `buildup_slope`：它是「累积(bid−ask) 对档位序号的单一斜率 ÷ 总深度」，不是双侧斜率差。

#### 7.7.9 「翻号」的统一判定规则（新增）

§3 判据 5 只说「方向一致」，未给机械判定。固定为：**该子口径 / 子集的净均值 < 0 即视为翻号**，不另设显著性门槛（§3 判据 5 明文「不要求都显著」）。适用于：1h 块、剔波动时段、BTC/ETH 子集、剔贡献币、§7.2.1 的历史标准差稳健性。

#### 7.7.10 横截面最小样本（新增）

- 每槽每侧 `k = floor(0.10 × n_coins)`；`n_coins < 5` 时该槽不触发。
- `n_coins` 只计当槽有有效 z 的币（定义见 §7.3 补充）。
- 该规则在看数前固定；若实测触发数不足 300，按 §3 延长采集，**不调 k**。

#### 7.7.11 判据 4 的门控地位（2026-10-23 追加，仅追加）

- 按 §7.7.2，`lo > 0` ⟺ `p < 0.025` 严格等价，故**判据 4 仅报告 p 值，不参与通过/否决的门控**；H1 报告值 p<0.05、H2 报告值 p<0.025（Holm/Bonferroni 上界），两者的实际否决门槛均由判据 1 的 CI 下界隐含。
- 判据 3「主口径单独成立」继续要求 W=60s/h=300s 配置**单独**满足判据 1、2、5 与样本量/经济阈值（§3），稳健格子（W=300s/h=900s）只作参考，不否决。
- 「样本不足（n < 300）」与「证伪」在程序退出码上区分：0=通过、1=证伪、3=样本不足（§7.5 的「不可判定，延长采集」），供 cron/CI 区分语义。

#### 7.8 判据 2 的分腿输出（2026-10-23 追加，仅追加）

- §3 判据 2 的方向定义是「OFI+ → 收益+」，指向**多头腿**；而程序判定用的是多空**合并**净均值（`c2 = mean > 0`）。极端情形下多头腿为负、空头腿暴赚时，合并均值仍可 >0。
- 按 §7.5「判据 2 由判据 1 的 CI 下界 >0 隐含」，**判定口径不变**；本节只要求报告额外给出多/空分腿的 n 与净均值（`判据2 分腿（仅报告）` 一行），用于评估证据强度。
- 该行为**仅报告**，不参与 `passed`。本节在看数前固定；10-28 看过统计量之后再补此输出，等同事后调整报告口径，不可接受。

#### 7.9 运行手册（2026-10-23 追加，仅追加）

- **不得在实盘容器内执行**。生产容器配额 1 GiB / 2 核，实盘循环常驻 `anon ≈ 550 MiB`；runner 双 worker 峰值 `anon ≈ 905 MiB`。二者相加超配额，容器 `MemorySwap = 2 GiB` 故不会 OOM-kill，但全程换页，实盘会漏扫描 / 漏成交（实测 CPU 4.35%）。
- 用**独立容器**跑，数据卷挂载，日志单独落盘（除日志外不写入任何文件）：

  ```bash
  docker run --rm -m 1g --cpus 2 \
    -v hermes-deploy_hermes_data:/data \
    --entrypoint python3 hermes-deploy-hermes-trader:latest \
    /app/scripts/m1_ofi_eval.py --jobs 2 2>&1 | tee /data/m1_eval_20261028.log
  echo "exit=$?"
  ```

- `--jobs 2` 显式写死以保证可复现。程序默认并行度已按 cgroup **剩余 anon** 预算（450 MiB/worker）：独立容器空闲时算出 2，实盘容器内会降到 1（串行约 53 分钟），后者只作兜底、不作为正式执行方式。
- 先只报 `天数=`、`建槽完成`、`EXIT`、`ELAPSED` 四行；统计量按 §3 判据逐条出（§7.8 分腿行一并给出）。
- 退出码语义见 §7.7.11：0=通过、1=证伪、3=样本不足。
