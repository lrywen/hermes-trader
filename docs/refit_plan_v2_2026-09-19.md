## 2. 目标（G1–G3）

- **G1 可信回测**：回测的成交/止损/成本/并发语义与生产逐笔对齐，误差可自检（flat 模式 0 偏差），结论用按天块自助判定显著性。
- **G2 损耗拆解**：把毛利 → 净利链条拆成出场损耗、手续费、滑点、穿透、并发占用五段，每段有数字与复现命令（基准：毛利 +29.22 / 出场 −18.84 / 成本 −9.26 / 净 +1.10 bps 量级）。
- **G3 资金冻结纪律**：SHADOW→LIVE 由机械门禁控制，任何单点"看起来好"都不能放行；≥1 项块自助正面结果前禁止离开 SHADOW。

## 3. 八项新需求/变更点（相对旧 P1–P6 路线）

1. **B-1a-改（关键路径）**：① Phase2 交易所止损单价格镜像为 `floor×(1−10bps)`（Stop Market，5/5 实测 limitPx≈成交价×0.90）；② Phase1 静态 SL 与 DSL 硬止损取**先触及者**并建穿透模型（PURR 穿透 1.57pp，−3.236% vs cap 1.67%）；③ 逐笔带杠杆 `eff_max_loss=min(spot_cap, roe_cap_pct/lev)`，修 `bt_ra_exch.py:603-606` 硬编码 lev=1；④ `spot_cap=3.00[atr]` 支持（公式待 A-3 定案）。
2. **B-2 强制 maxc=2**：全部回测路径峰值并发 2（当前峰值 7；filt 结果由 +13.86% 翻为 −5.20%）。写入内核 guard，旧脚本无法绕过。
3. **B-3 币池 8→81**：用 bt_ready_pool=81；预热 4h/1h/5m 全齐（当前补 8 币 5m、3 币 1h）；DSL floor 占比 14.9% 需向实盘 52.6% 靠拢并给出解释。
4. **B-4 per-coin 滑点表扩 81 币**：替换统一半价差（实测 2.54 vs 0.31 bps）。
5. **B-5 P5-1bd 固化**：往返成本 9.26 bps（手续费 8.64 + 滑点 0.62）；flat 模式 5,453 笔 0 偏差自检进 CI。
6. **exchange_trigger 归因定案**：oid 9/10 Stop Market + Triggered + reduceOnly；`sl_buffer_bps=10`；347 订单中 154 单 triggered，每仓平均 8 次 cancel+replace；归因 28 交易所侧 / 22 本地 DSL / 1 无匹配；trading_loop.py:1445-1665 对账标签据此重标。
7. **B-12/13 SHADOW 硬门禁**：mode=LIVE 时无验收门记录拒绝启动；在既有 `HERMES_ENABLE_LIVE` 三守卫上做组合断言，不新建机制。
8. **方法论纪律**：显著性只用按天块自助；noise_band 之外 13 项已否证方向不复活；G1–G16 禁止项逐条遵守；权威配置只认容器内 `/data/.agent-config.json`（142 键），禁用仓库 65 键版本。

## 4. 技术路线（路径 A：内核增量，不重写生产）

- 所有回测语义改动落在 `hermes_trader/backtest/` 内核与 scripts/bt_* 研究脚本；生产代码只接受两类触碰：B-12/13 门禁增强、对账归因标签重标。
- 内核 guard 负责把纪律变成硬错误（maxc、lev、数据 PIT、成本表齐全度）。
- 每项改动必须有：离线单测 + flat 0 偏差自检 + 复现命令 + 数字进 SCOREBOARD。

## 7. 验收判据（10 条）

1. 全量离线测试 ≥ W0 冻结值，CI 硬护栏随之上抬且全绿。
2. flat 模式全样本 0 偏差自检通过（当前基线 5,453 笔）。
3. 回测止损路径与生产 exchange_trigger 语义一致（10bps buffer、先触及者、reduceOnly Stop Market）。
4. 每笔交易 `eff_max_loss` 逐笔带杠杆，lev=1 旧路径在 guard 下拒绝运行。
5. 任意回测路径 maxc 恒为 2，guard 可实测拦截。
6. 81 币三周期缓存齐全（或每缺口有书面豁免）。
7. per-coin 滑点表覆盖全部回测币，成本合计与 9.26 bps 基准可对账。
8. 毛利→净利五段损耗数字齐备且有复现命令。
9. mode=LIVE 无验收门记录时系统拒绝启动，并有单测与手动验证记录。
10. 显著性结论只来自按天块自助；三结局（A/B/C）之一被数据明确选中并归档。
