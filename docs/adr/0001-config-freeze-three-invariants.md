# ADR-0001：配置冻结与三条不变量

- 状态：Accepted
- 日期：2026-09（原始 `0.4_ADR-001` 约成稿 2026-09 上旬；本重建版 2026-09-20）
- 重建说明：原临时报告 `0.4_ADR-001_配置冻结与三条不变量`（含「三条不变量 + 5 个裂痕 +
  6 条待办」）随 2026-09-16 临时目录清理丢失（见
  `docs/research/2026-09/README.md` 第 18 项）。本文件依据现存引用
  （统一改造文档 L129/L684/L903）重建核心不变量；**原始逐条文本、5 裂痕、6 待办不可得**，
  若日后从宿主快照/云端导出找回原件，应核对并补全。

## 背景

系统长期在 `mode=SHADOW` 影子模式运行。历史上配置在容器 `/data/.agent-config.json`
内独立演化、不进 git，且无变更审计（如 2026-09-08/09 手动把 `dsl_exit.max_loss_pct`
2.5→1.0，无记录；见 W3 A-1 SCOREBOARD）。一条字符串误改（SHADOW→LIVE）即可让未经验证的
策略动用真实资金。原 ADR 因此提出三条不变量，但当时**没有强制机制**（无 CI、无启动断言）。

## 不变量（据现存引用重建）

1. **资金冻结**：在出现至少一项通过按天块自助检验的正面结果之前，系统不得离开
   `mode=SHADOW`；任何单点「看起来好」都不构成放行理由。
2. **LIVE 切换必须过验收门**：`mode` SHADOW→LIVE 是受保护变更，必须通过统一改造文档
   §5.2 的验收门（判据 1–5 全过 + 块自助显著性裁定为结局 A），并留下可核验的验收门记录。
3. **显式确认不可绕过**：`HERMES_ENABLE_LIVE=true` 与真实 `mode=LIVE` 的组合必须经过
   显式、可审计的确认路径，防止误改一个字符串即进入实盘。

> 注：以上是现存材料能支撑的核心语义。原件「三条不变量」的精确措辞、5 个裂痕、
> 6 条待办待原件找回后补全；本重建版不假装逐字还原。

## 强制执行（W5 / B-12、B-13 落地）

不变量不再只是约定：

- 启动时对 `HERMES_ENABLE_LIVE` 与 `mode` 组合做断言（B-12，在既有三守卫上组合，不新建机制）；
- `mode=LIVE` 而无验收门记录时拒绝启动并列出缺失项（B-13）；
- 本 ADR 目录（F-3）把资金安全变更纳入「必须留 ADR」流程。

## 后果

- 被否证的影子候选（E-1/E-2）不得借配置改动转正；
- 配置演值的「无审计漂移」通过 ADR + 门禁收口；
- 不限制 SHADOW 下的研究自由，只冻结真实资金出口。
